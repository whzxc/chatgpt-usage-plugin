# Distribution

Source and installable marketplace belong to this repository. `main` contains TypeScript, React, launchers, documentation and build tools. `stable` is generated only by an explicitly authorized release.

The Plugin workflow runs only through manual dispatch. Build jobs on Apple Silicon macOS and Windows x64 install npm dependencies, type-check UI/server, bundle JavaScript and the self-contained UI, run the existing MCP artifact check, and upload platform ZIPs with SHA-256 checksums. There is no Rust toolchain or platform compilation. CI selects its Node through `CHATGPT_USAGE_NODE`; this does not validate host discovery. See [runtime support](runtime.md) for installed-host boundaries.

For a release, synchronize `package.json`, `package-lock.json` and both `plugins/usage/plugin.json` and `plugins/usage/.codex-plugin/plugin.json`. Update `docs/release-notes.md`, run `npm run check`, `npm run check:format` and `npm run plugin:build`, and accept the two panels in each supported installed host. Runtime layout changes require renewed host acceptance.

After publication is authorized, create `v<version>` on the verified source commit and dispatch the Plugin workflow on that tag with `publish=true`. The publish job verifies ZIP checksums, identical cross-platform bundles and metadata, matching source/tag identity, and every runtime payload hash. It advances `stable` and attaches release archives using the repository GITHUB_TOKEN. Pushes, PRs and tag creation do not trigger builds or publication.

Both platform archives contain the same generated server/worker bundles and shell, CMD and PowerShell launchers. On macOS the extensionless MCP command is a shell script; on Windows the host resolves its `.cmd` sibling. Generated payloads include the embedded UI, third-party notices and release provenance; source paths, caches, credentials and host binaries are excluded. These archives are not notarized apps or Authenticode-signed installers.

## Package layout and compatibility

Each `plugins/usage/` payload contains root `plugin.json`, root `mcp.json`, `assets/`, `bin/` and `LICENSE`. Portable identity uses the Agent Plugins 1.0.0 schema; host presentation lives in `extensions.com.openai`. The stdio MCP configuration uses `./bin/chatgpt-usage` and `${PLUGIN_ROOT}` as its working directory. The host resolves `./` commands from the plugin root; `${PLUGIN_ROOT}` is not supported in `command` (only arguments, environment values and working directory). Portable configuration deliberately omits legacy-only `env_vars` and `tool_timeout_sec`; environment inheritance and timeouts belong to the host.

The package also retains `.codex-plugin/plugin.json` and `.mcp.json`. On 2026-10-16, ChatGPT's bundled CLI `0.162.0-alpha.17.2` was verified to discover both entrypoints with portable manifests after correcting the launcher command. `command: ${PLUGIN_ROOT}/bin/chatgpt-usage` silently drops the MCP server even though it passes the published JSON schema. The host's [stdio parser](https://github.com/openai/codex/blob/main/codex-rs/codex-mcp/src/agent_plugin_config.rs) requires a bare executable name or a contained `./` path. Both layouts remain until the supported hosts accept a portable-only package; then remove the legacy files and their consistency checks. No installed plugin or host configuration is modified by build/check commands.

The [official packaging documentation](https://developers.openai.com/plugins/build/plugins) defines root identity and MCP configuration as canonical. When `extensions.com.openai` exists, its settings replace (rather than merge with) the legacy overlay. The current [plugin schema](https://agent-plugins.org/schemas/1.0.0/plugin.schema.json) and [MCP schema](https://agent-plugins.org/schemas/1.0.0/mcp.schema.json) are cached under `tooling/schemas/`. Build-only Ajv validates them without network access; artifact checks and marketplace assembly also reject divergent identities, presentation metadata and launch commands.

The [entrypoint/display-mode specification](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md) assigns the global entrypoint to global navigation and the thread entrypoint to a conversation content tab/side panel. Resource contents declare `openai/ui.availableDisplayModes: ["fullscreen"]` and `preferredDisplayMode: "fullscreen"`, also advertised during app initialization. There is no `sidebar` display-mode enum: `thread` selects that surface. Both entrypoint tools use a separate 20×20 currentColor SVG with a 1.5 stroke; the plugin/server icon is unchanged.

## Local host acceptance

Build with `npm run plugin:build`, then register/install the extracted marketplace only when ready to change your host installation (see README). Reopen Usage overview and Task usage: check fullscreen overview, task side panel and theme-aware icons. Open a recorded tool call and verify that output has no leading/trailing blank lines, retains internal whitespace, and copies exactly as displayed. Installed-host acceptance is separate from artifact checks; Windows requires its own host acceptance.
